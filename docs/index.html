01 / LA PREGUNTA

¿Podemos comparar estas dos máquinas?

M01 tiene cinco temperaturas elevadas consecutivas. En M02 faltan dos mediciones de potencia durante una intervención. ¿Hay un fallo? ¿Una parada? ¿Cuál consume menos por pieza? La práctica enseña a separar lo observado de lo que aún no podemos afirmar.

FuenteMuestra
Sensores · JSON Lines45 recepciones, con duplicado, conflicto, unidad incorrecta, máquina desconocida y fecha ilegible.
Producción · CSVDos filas: M01 produce 10 piezas correctas; M02 produce 8.
Mantenimiento · CSVUna intervención planificada en M02, de 08:04 a 08:06 UTC.
Catálogo · PostgreSQLDos máquinas, cuatro sensores, unidades, cadencias y límites.
Los valores son didácticos y sintéticos. Una alerta por umbral no confirma un fallo mecánico. Una ausencia de datos no demuestra una parada.
02 / COMPRENDER LOS SERVICIOS

La misma lógica del trabajo original.

El generador prepara los datos; PostgreSQL mantiene el catálogo; el pipeline valida, integra y calcula. Jupyter muestra el proceso y el panel lee únicamente publicaciones completas. La carga ordinaria funciona sin abrir cuadernos.

Abrir esquema completo. En pantallas pequeñas, desplázalo horizontalmente. No se necesitan Hadoop, Kafka ni un clúster Spark para esta sesión.

03 / ANTES DE CLASE

Descarga, construye y ensaya.

Necesitas Docker Desktop y Docker Compose. En el MacBook Air M4 se ha probado ejecución ARM64. Deja alrededor de 2 GB de memoria disponibles para estos servicios y espacio para las imágenes. No instales Python ni PostgreSQL en macOS.

Terminal de macOS · carpeta del proyecto
git clone https://github.com/iesataulfoargentasor/industrialdata-mini-ra1.git
cd industrialdata-mini-ra1
bash preparar.sh
bash iniciar.sh

La primera construcción requiere Internet: hazla antes de los 90 minutos. Si utilizas ZIP, abre Terminal en la carpeta real descomprimida. El arranque genera los mismos datos sin sobrescribir originales diferentes.

05 / COMPROBAR A MANO

Resultados que puedes defender.

ResultadoValor esperadoInterpretación
Primera carga45 = 40 + 1 + 4Nuevas, duplicadas y rechazadas: categorías excluyentes.
Temperatura M01Un episodio [08:02, 08:07)Cinco muestras consecutivas sobre 80 °C.
Energía M011 kWh · cobertura 100 %6 kW × 10/60 h. Con 10 piezas: 0,1 kWh/pieza.
Energía M020,35 kWh · cobertura 70 %No evaluable por pieza: la energía está incompleta.
Muestras M02_power8 de 10 · cobertura 80 %Dos muestras ausentes; diferente de cobertura energética.
Segunda carga0 nuevas + 41 duplicadas + 4 rechazadasSiguen 40 observaciones consolidadas y un episodio.
La trampa didáctica: 0,35 / 8 = 0,04375 parece mejor que 0,1, pero compara energía incompleta con producción completa. M02 no puede declararse más eficiente. Además, piezas de productos distintos requieren contexto para una comparación industrial.
¿Por qué dos muestras ausentes dejan tres minutos sin energía estimada?

Hay potencia a las 08:03 y a las 08:06. El segmento dura 180 segundos, más de 1,5 veces la cadencia de 60 segundos. Se excluye completo. Quedan siete de diez minutos cubiertos. No se rellena el hueco con ceros ni se supone potencia constante durante él.

06 / VERIFICAR Y CONSERVAR

Pruebas, recarga y persistencia.

Terminal de macOS · carpeta del proyecto
bash comprobar.sh

Ejecuta 21 casos automáticos, publica una carga y consulta PostgreSQL. Si lo haces antes de clase, la siguiente carga ya será una repetición; el cuaderno 01 sigue mostrando en memoria los recuentos iniciales. No borres datos para aparentar un primer arranque.

Terminal de macOS · carpeta del proyecto
docker compose restart db dashboard notebook
docker compose run --rm pipeline python scripts/comprobar_postgres.py

La comprobación posterior al reinicio no regenera datos. Verifica catálogo, auditoría y publicación. Para operar sin notebook:

Terminal de macOS · carpeta del proyecto
docker compose run --rm pipeline

Para parar conservando el trabajo:

Terminal de macOS · carpeta del proyecto
bash parar.sh

Para reanudar: bash iniciar.sh. No uses down -v: elimina el volumen de PostgreSQL. Los cuadernos y archivos de datos permanecen en las carpetas del proyecto.
